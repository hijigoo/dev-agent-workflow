01 / OVERVIEW

한눈에 보는 전체 흐름

자동화의 종착점은 코드 병합이 아니라 검토 가능한 Issue와 draft PR입니다. Agent는 반복 작업을 빠르게 수행하고, 범위·위험·승인·배포 판단은 사람이 유지합니다.

01 · SIGNAL

과업 등록

Jira, Slack, 독립 Work Intake 앱에서 배경·인수 조건·제외 범위를 작성합니다.

02 · ASSIGN

Agent 할당

GitHub Issue에 agent-ready를 붙이고 Copilot을 선택합니다.

03 · BUILD

격리 구현

Cloud Agent가 전용 branch에서 코드·테스트·draft PR을 만듭니다.

04 · VERIFY

자동 검증

Unit, UI, E2E, quality evidence와 CodeQL을 병렬 실행합니다.

05 · REVIEW

사람 리뷰

요청자 기능 확인과 독립 reviewer 승인 후에만 merge합니다.

06 · APPROVE

운영 승인

병합 후 재평가하고 production Environment에서 다시 승인합니다.

07 · DEPLOY

ACA 배포

OIDC 로그인, ACR build, revision 배포, HTTPS smoke를 수행합니다.

단계 GitHub에서 보이는 상태 자동으로 실행되는 작업 사람이 확인·결정할 일 완료 증거

04 / HANDS-ON

직접 테스트하는 방법

현재 준비된 저장소에서 실제 Issue를 Copilot에 할당하고, Agent session·draft PR·검증·사람 승인· ACA 배포까지 순서대로 확인합니다. 자동 merge는 사용하지 않습니다.

번호 안내: 01 · PR Validation에서 PR 1/2~2/2가 성공한 뒤 사람이 merge하면, 별도 02 · Production Deployment에서 Main 1/3~3/3이 실행됩니다.

01

Agent-ready Issue를 생성합니다

Cloud Agent task 양식을 선택하고 한 Agent session 안에서 끝낼 수 있는 작은 과업을 작성합니다.

Repository → Issues → New issue → Cloud Agent task 
제목: [Agent] 한국어 회의실 검색 intent 지원

인수 조건:
- 한국어 검색 요청을 room-search로 분류
- 기존 영어 요청 동작 유지
- API unit·React component·Playwright test 추가

제외 범위:
- 외부 LLM/API 도입
- Azure·workflow 변경
New issue 열기 기대 결과 · agent-ready label이 붙은 열린 Issue
02

Issue를 Copilot에 할당합니다

Issue 오른쪽 Assignees에서 Copilot을 선택합니다. 별도 수동 workflow 실행은 필요하지 않습니다.

Issue → Assignees → Copilot
  • GitHub가 Copilot cloud agent session을 시작합니다.
  • 00 · Cloud Agent — Reproducible Setup으로 Python·Node 환경을 준비합니다.
  • Issue timeline에서 session과 연결된 PR 링크를 확인합니다.
기대 결과 · copilot/* branch와 Running Copilot cloud agent 실행
03

Cloud Agent의 Draft/WIP 진행 상황을 확인합니다

Agent는 작업 시작과 함께 Draft PR을 만들고 코드를 계속 추가합니다. 코드 생성과 자체 테스트가 끝나면 Ready for review로 전환합니다.

Issue timeline → Connected pull request → Files changed
  • Issue 인수 조건과 실제 변경 파일이 일치하는지 확인합니다.
  • 제외 범위 밖 dependency·workflow 변경이 없는지 확인합니다.
  • Draft/WIP: Agent가 아직 작업 중이며 PR Validation job은 실행되지 않습니다.
  • Ready for review: Agent 작업이 끝나고 사람 검토와 자동 검증을 시작합니다.
기대 결과 · [WIP] 제거와 Ready for review 전환
04

01 · PR Validation의 PR 1/2~2/2를 실행합니다

PR이 Ready for review가 되면 품질 검증과 CodeQL이 한 run에서 순차 실행됩니다. Draft 상태에서는 workflow run 자체가 생성되지 않습니다.

Pull request → Checks → Approve and run workflows 또는 Re-run all jobs
  • PR 1/2: Python, React lint/unit/build, Playwright E2E, quality artifact
  • PR 2/2: Python과 JavaScript/TypeScript CodeQL
기대 결과 · Python, Web, Browser E2E, CodeQL check 모두 Success

기능 확인과 코드 승인을 분리합니다. 수정이 필요하면 새 Issue 대신 기존 PR에서 요청합니다.

05 / GOVERNANCE

자동화와 승인 경계

속도를 높이되 통제권은 넘기지 않습니다. Agent는 조사·수정·검증을 수행하지만, 범위 변경, 위험 수용, 코드 병합, 운영 배포는 반드시 사람이 결정합니다.

Agent가 수행하는 일

  • Issue와 repository instructions 기반 계획 수립
  • 전용 branch에서 코드와 회귀 테스트 작성
  • draft PR, 변경 요약, 위험과 rollback 보고
  • 리뷰 feedback에 따른 후속 수정
  • security·quality signal의 정형 분석
중요 원칙 Agent의 완료 기준은 “코드를 작성함”이 아니라 “사람이 판단할 수 있는 증거를 제공함”입니다.

사람이 유지하는 4개 Gate

G1

과업 범위 승인

인수 조건, 제외 범위, 데이터·권한 제약을 확정합니다.

G2

Workflow 실행 승인

Agent가 만든 PR의 Actions 실행을 repository owner가 허용합니다.

G3

PR 독립 승인

요청자 기능 확인과 독립 reviewer 코드 승인을 분리합니다.

G4

Production 배포 승인

Environment required reviewer 승인 전에는 OIDC와 Azure 변경이 시작되지 않습니다.
