01 / OVERVIEW

한눈에 보는 전체 흐름

자동화의 종착점은 코드 병합이 아니라 검토 가능한 Issue와 draft PR입니다. Agent는 반복 작업을 빠르게 수행하고, 범위·위험·승인·배포 판단은 사람이 유지합니다.

01 · SIGNAL

과업 등록

Jira, Slack, Work Intake에서 배경·인수 조건·제외 범위를 작성합니다.

02 · ASSIGN

Agent 할당

GitHub Issue에 agent-ready를 붙이고 Copilot을 선택합니다.

03 · BUILD

격리 구현

Cloud Agent가 전용 branch에서 코드·테스트·draft PR을 만듭니다.

04 · VERIFY

자동 검증

Unit, UI, E2E, quality evidence와 CodeQL을 병렬 실행합니다.

05 · REVIEW

사람 리뷰

요청자 기능 확인과 독립 reviewer 승인 후에만 merge합니다.

06 · APPROVE

운영 승인

병합 후 재평가하고 production Environment에서 다시 승인합니다.

07 · DEPLOY

ACA 배포

OIDC 로그인, ACR build, revision 배포, HTTPS smoke를 수행합니다.

02 / SEQUENCE

End-to-End 시퀀스

화살표는 실제 정보와 제어의 이동을 나타냅니다. 붉은 선은 사람의 명시적 결정, 녹색 선은 검증된 성공 결과입니다. 작은 화면에서는 좌우로 스크롤할 수 있습니다.

03 / AUTOMATION

04 / GOVERNANCE

자동화와 승인 경계

속도를 높이되 통제권은 넘기지 않습니다. Agent는 조사·수정·검증을 수행하지만, 범위 변경, 위험 수용, 코드 병합, 운영 배포는 반드시 사람이 결정합니다.

Agent가 수행하는 일

  • Issue와 repository instructions 기반 계획 수립
  • 전용 branch에서 코드와 회귀 테스트 작성
  • draft PR, 변경 요약, 위험과 rollback 보고
  • 리뷰 feedback에 따른 후속 수정
  • release·security·quality signal의 정형 분석
중요 원칙 Agent의 완료 기준은 “코드를 작성함”이 아니라 “사람이 판단할 수 있는 증거를 제공함”입니다.

사람이 유지하는 4개 Gate

G1

과업 범위 승인

인수 조건, 제외 범위, 데이터·권한 제약을 확정합니다.

G2

Workflow 실행 승인

Agent가 만든 PR의 Actions 실행을 repository owner가 허용합니다.

G3

PR 독립 승인

요청자 기능 확인과 독립 reviewer 코드 승인을 분리합니다.

G4

Production 배포 승인

Environment required reviewer 승인 전에는 OIDC와 Azure 변경이 시작되지 않습니다.

05 / CONTINUOUS WORK

신규 기능 외 자동 과업

같은 Issue → Agent → PR → Evidence → Review 패턴을 보안과 품질 개선에도 적용합니다. 자동 탐지와 자동 병합은 분리합니다.

SECURITY SIGNAL

GHAS 취약점 조치

Dependabot은 의존성을, CodeQL은 code path를 담당합니다. suppress가 아니라 최소 수정과 방어 테스트를 요구합니다.

Alert → Security Agent → Regression → Security reviewer
QUALITY SIGNAL

주간 품질 개선

민감 원문 없이 fallback·latency·tool success를 분석하고, 사람이 선택한 개선 후보만 별도 구현 Issue로 전환합니다.

04 Optional → Read-only analysis → Owner decision → Agent PR
06 / CUSTOMER DEMO

45분 시연 진행안

화면을 많이 이동하지 않고 Issue, Agent session, PR checks, Environment 승인, 배포 사이트 순서로 보여줍니다. 각 단계에서 “누가 결정하고 어떤 증거가 남는가”를 강조합니다.

진행 순서

목표와 역할 분리 · 5분

Agent를 개인 도구가 아닌 비동기 팀원으로 정의합니다.

Mini Agent 앱 · 5분

외부 key 없이 intent, answer, pipeline trace를 실행합니다.

Issue → Cloud Agent · 10분

한국어 회의실 검색 과업, Copilot assignee, session log를 확인합니다.

Draft PR와 검증 · 10분

Agent diff, 01/02 checks, E2E artifact와 리뷰 feedback을 봅니다.

운영 자동 과업 · 10분

04 quality와 GHAS remediation의 공통 패턴을 설명합니다.

승인형 ACA 배포 · 5분

평가 성공, production 승인 대기, live health evidence를 확인합니다.
